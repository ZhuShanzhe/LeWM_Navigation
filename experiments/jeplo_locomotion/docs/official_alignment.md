# 官方配置基准

## 基准范围

基准分为两层：**官方 README 部署链路**和**论文表 II 定量评测**。前者以发布代码、部署权重和明确的启动参数为准；后者还需要检查点对应关系、初态、指令、遮挡、成功判定等评测协议。两者不能混用。

冻结来源：[JEPLO 官方提交](https://github.com/ASIG-X/JEPLO/tree/460e2272907af053d6e66b57fec71fdbe6ca1774)。机器可读设置见[官方配置](../configs/official_readme_profile.json)。原有 385 次结果是独立诊断，不计入这一基准，不据此推断官方真实性能。

## 已核实的配置

| 项目 | 官方仿真部署设置 | 核验要求 |
|---|---|---|
| 仿真 | 官方定制 unitree_mujoco，启用 `--lidar` | 保留官方机器人、动力学、DDS 桥接、地形切换行为 |
| 感知 | 官方 depth publisher，`--sim --downsample-rate 4 --fov 25x60` | 保留点云顺序、投影、5 扫描累积和异步发布 |
| 遮挡 | README 示例默认启用随机 cage mask | 不得称为无噪声 Standard；记录每次实际遮挡 |
| 动作 | `--raw-actions` | 不加入默认动作平滑或髋关节半幅 |
| 安全检查 | `--ood-count-threshold 15` | 保留关节限位、OOD 检测与 damping；记录触发 |
| 通信 | `--net lo`，DDS domain 1 | 仅本机仿真，不连接机器人网络 |
| 频率 | LiDAR 20 Hz，深度 10 Hz，策略 50 Hz，估计器 10 Hz | 同时记录实测周期、延迟和仿真时间/墙钟时间比 |
| 推理 | ONNX Runtime 1.22.0 + TensorRT 10.9，CUDA 12.8，cuDNN 9 | 记录实际 provider、库版本、精度与测试样本误差 |
| 模型 | `deployment/go2_deploy/model/pretrained` | 固定两个 ONNX SHA-256，不与 training 导出混用 |

来源：[官方 README 的仿真部署与环境说明](https://github.com/ASIG-X/JEPLO/blob/460e2272907af053d6e66b57fec71fdbe6ca1774/README.md)。这里使用的是 README 推荐参数，不能以源码默认参数代替。旧测试的默认模式包含平滑、髋关节半幅和不同点云采样设置，因此其转向或障碍表现不代表官方推荐配置。

## 验收顺序

1. **版本与模型**：校验源码提交、资源和权重哈希；记录全部依赖版本。缺项不得标为通过。
2. **推理与接口**：用官方输入/输出样本校验实际推理后端；核验观测排列、动作缩放、深度消息、关节限位与安全分支。
3. **官方链路冒烟测试**：先验证初始化、站立、零指令、平地前进、旋转，再用官方场景验证楼梯和箱体。保存实际消息和频率证据，不以“程序启动成功”代替闭环通过。
4. **预先冻结批量协议**：固定场景文件、初态/随机种子、指令时间表、超时和通过条件，再运行全部病例。失败、停机、超时和无效运行分别记录，不能悄悄删除重跑。
5. **报告分组统计**：报告每种地形/遮挡条件的样本数、成功率及置信区间、跟踪误差、跌倒、卡住、OOD 停机与时序异常。配对对照使用相同病例；不混合不同任务得到总成功率。

官方链路运行失败时不得自动切回旧同步评测器并沿用“官方基准”名称。任何无窗口、日志或构建适配均保存差异，说明是否影响物理、感知、控制和调度。

## 论文复现的未确认项

论文表 II 涉及 50 cm 箱体和 20 cm 高、30 cm 深的楼梯，以及不同遮挡条件；公开交互式示例场景不自动等同于表格场景。论文要求的每组 500 次不能由旧有每组 3–5 次代替。详见[论文](https://arxiv.org/html/2609.15770v1)。

以下问题仅整理，**不向作者发送**：

1. 部署目录中的 policy 与 sensor estimator 是否正是表 II 的检查点？对应训练编号和迭代数是什么？
2. 表 II 所用 MuJoCo、Unitree SDK2 版本及完整场景 XML 是否可提供？公开代码缺少的定制 MuJoCo simulate 依赖如何取得？
3. 箱体尺寸、楼梯级数、摩擦、接触求解器、初始位置/朝向/关节状态如何设置？朝向是否均匀随机？
4. 控制指令如何生成，是否人工操作、航向闭环或固定速度？初始化及每次重置流程是什么？
5. “成功”对应何种位置、高度和持续时间条件？试验超时、跌倒与 OOD 停机如何计数？
6. Standard 是否关闭 cage mask？Blob/Cross/Cut/Stripe 的具体生成代码、强度、更新频率和种子是什么？
7. 500 次试验如何分组？表格标准差按哪些重复实验计算？
8. 论文实验是否使用 README 中的 raw actions、下采样 4 和 OOD 阈值 15？是否还有参数覆盖？
9. 异步评估如何处理低实时率、消息丢失与延迟？推理使用的 provider、精度与缓存设置是什么？

上述信息未确认时，结果最多标记为“官方部署配置下的自定义协议测试”，不能宣称已复现论文数值或已排除全部配置偏差。

## 已执行的验收

- 源码、模型与启动参数检查已通过；原始 JEPLO 检出目录保持未修改。
- 对错误提交、错误权重、错误采样、错误动作模式、真机网络、无依据论文结论和错误命令的 7 个反例，检查器均拒绝通过。
- 官方 C++ 点云处理函数通过下采样、归一化、五帧累积及遮挡测试。
- ORT 1.22.0 + TensorRT 10.9 在官方测试样本上通过部署容差；执行 profile 确认实际使用 TensorRT。策略最大绝对误差 0.0050347，估计器 0.0021752。此项使用 Python ORT API 与官方模型，不代表 C++ 控制器及闭环已经通过。
- 使用官方 `TerrainSwitcher` 直接载入公开场景：默认楼梯上行段为 20 级、每级高 15 cm、深 25 cm，楼梯几何的滑动摩擦系数为 3；不是论文表 II 的 20 cm / 30 cm 楼梯。双箱示例的两个平台顶面分别离地 30 cm、70 cm，单个平台平面尺寸为 1.5×1.5 m，也不是论文单个 50 cm 箱体。该检查使用 MuJoCo 3.3.7，仅核验几何与切换行为。
- 官方 ZMQ 感知分支以合成点云完成无遮挡和默认 cage mask 两轮异步测试：输入各 140 帧，预热后各收到 50 帧，输出约 10 Hz。该测试不运行机器人控制器，不能当作运动性能测试。

构建适配仅排除仿真不使用的 ROS 分支，保留官方 ZMQ 点云处理与发布代码；保存原始/适配文件哈希及差异。源码相同不等同于完整闭环时序已验证。

原生仿真、C++ 控制器、ZMQ 感知和 DDS 通信已完成一次初始化及 10 秒零指令闭环：官方控制器自身的 TensorRT 样本测试通过，接收 LiDAR 数据 539 帧；进入就绪状态后的观测频率约 20 Hz。程序正常闭环不等于已证明全部运动能力。

原生构建记录：MuJoCo 使用 3.3.7，Unitree SDK2 冻结到 `63096d0ac0c5d2dec9d6e0c22cd5233410ca2f36`；两者均不能声称是论文实际版本。仿真仅排除依赖未提供 MuJoCo 扩展接口的可选 RGB-depth 分支，保留默认 LiDAR、物理循环和地形切换；控制器源码未改。服务器通过虚拟显示运行原生仿真，ORT 使用同版本官方 wheel 中的共享库与 1.22.0 头文件，TensorRT 使用 10.9 官方 Python 分发中的库。CUDA 实测 12.8、cuDNN 9.8。

## 短测试的解释

短测试使用常值机体速度命令和默认随机 cage mask，每个配置只有单次记录；不能据此估计真实成功率，也不能直接与旧同步评测器形成因果对照。

- 前进指令 0.25 m/s，约 8 秒运动观察段的平均位移速度 0.219 m/s，包含启动过程。
- 转向指令 1 rad/s，同样观察段平均转向速度 0.755 rad/s；没有翻倒或 OOD 停机记录，但不等于速度跟踪完全准确。
- 官方双箱示例中，长时间持续前进的记录达到约 1.03 m 机身高度，随后越过平台边缘并翻倒。登箱与下落是不同阶段，不能把这条记录整体解释成“无法登箱”。
- 官方楼梯示例的单次常值指令记录未完成登顶，最高机身高度约 1.80 m，之后翻倒。样本量、遮挡、控制指令和任务定义均不同于论文，不能用这一例反驳表 II。

为分离登顶和继续走下平台的影响，额外定义“登顶后停止并保持 2 秒”的示例测试：箱体沿初始朝向前进距离至少 4.15 m、机身高至少 0.90 m；楼梯对应 8.05 m 和 3.15 m；竖直方向余弦需大于 0.8。**这是本项目的示例停止条件，不是已确认的官方成功判定。** 长指令原记录保留，不能将两次不同随机遮挡的结果当作严格配对实验。

双箱登顶停止记录通过该自定义保持条件，停止后机身高度约 1.01 m，对应 70 cm 平台上站立。它证明了该次公开示例的登顶行为，不能被扩展为“70 cm 箱体普遍可靠”或论文成功率复现。

这些翻倒记录中没有触发扭矩/关节速度 OOD 停机，说明这一安全机制不能被当作通用跌倒检测器，更不能据此认证真机安全。

**目前通过的是部署链路及组件验收，论文定量协议尚未确认；不能据此发布论文成功率的复现结论。** 证据见[验收记录](../results/README.md)。
