# JEPLO 部署接口与运动评测协议

## 范围与版本

使用官方冻结部署权重，不训练、不微调，不连接或控制机器人。环境为三维 MuJoCo + 官方 Go2 机器人资源；模型接收 LiDAR 距离图与本体状态，不接收示意视频中的 RGB 画面。评测程序是独立同步实现，不是官方 C++ / ROS / DDS 全链路，也不是论文原始 benchmark。

- 官方仓库：<https://github.com/ASIG-X/JEPLO>
- 固定提交：`460e2272907af053d6e66b57fec71fdbe6ca1774`。
- 运行环境：Python 3.11.16、MuJoCo 3.3.7、ONNX Runtime CPU 1.30.0、NumPy 2.4.6。
- 服务器工作目录：`/root/autodl-tmp/jeplo_eval_20260928`。
- 权重位置：`JEPLO/deployment/go2_deploy/model/pretrained`。
- policy SHA256：`ffe8318312ac2e27a159115a70e3f12ddbb7444d7aa1325a22cce57223a05520`。
- sensor_estimator SHA256：`efe563d65e9aaab6626c816ba420d7e193e202259af65f64f313b0d30a436ba4`。

训练导出目录中的同名文件不是这一对部署权重。两组文件在相同输入下的输出不同，不得混用或仅根据文件名判断版本。

## 接口约定

| 项目 | 约定 |
|---|---|
| 上层指令 | 机体坐标系 `[vx, vy, wz]`，单位 m/s、m/s、rad/s；x 向前、y 向左、正 yaw 逆时针 |
| 指令范围 | vx、vy 各 ±1.5 m/s；wz ±3 rad/s，来自部署 config.json |
| 关节次序 | FL、FR、RL、RR 的 hip；随后相同顺序的 thigh；最后 calf |
| SDK 电机映射 | `[3,0,9,6,4,1,10,7,5,2,11,8]` |
| 本体观测 | 45 维：角速度×0.25、机体重力方向、速度指令×[2,2,0.25]、关节相对默认位置、关节速度×0.05、上一原始动作×0.1 |
| 历史 | 10 帧，共 450 维，新帧在前；每个 episode 重置历史与循环状态 |
| 深度输入 | `[1,2,25,60]`，距离除以 2 m；无回波/缺失值为 1；不是 RGB-D 相机直接输出 |
| 时序 | 物理 500 Hz；策略 50 Hz；估计器 10 Hz；LiDAR 20 Hz；累积最近 5 次扫描，10 Hz 发布 |
| 状态尺寸 | 从部署 ONNX 核实：feature 512、hidden 512，而非依赖源码中的初始化占位尺寸 |
| 默认动作 | 0.8×新原始动作 + 0.2×上一原始动作；髋关节再乘 0.5；所有动作乘 0.25 后加默认角度 |
| PD | kp=28、kd=1.1；MuJoCo 执行器物理限幅保留 |
| 限位 | 官方关节范围两端收缩 5%，接近收缩后边界 10% 区域时，禁止目标继续向外推进 |
| 安全阈值 | PD 力矩代理 >30 Nm 或关节速度 >25 rad/s，连续 20 个策略步则记为 safety_stop |

`raw_actions` 只去掉平滑与髋关节半幅处理；仍保留关节限位和安全阈值。不能将它理解为移除全部保护。

干净感知条件对应 25×60、downsample=1、5 帧累积，关闭人工 cage mask（相当于官方 `--no-cage-mask`）。不声称复现默认 publisher 的全部合成遮挡设置。初始站立 0.5 秒后，用一个实际 raycast 帧启动；与真机异步启动及遥控站立过程不同。

## 一致性检查

部署模型使用各自官方 10 个参考样本。策略最大绝对误差 0.00503445，估计器最大绝对误差 0.00269607。两者通过官方部署代码采用的最大/平均误差容差，但没有通过额外采用的严格 `rtol=1e-4, atol=1e-5` 检查。误差原因未完全定位，不标记为逐元素精确一致。

另外核对了关节映射、历史排列、默认动作变换及更新频率。独立辅助接口通过 10 项离线单元测试，覆盖指令字节序、长度、限幅、NaN/Inf 拒绝、世界到机体坐标变换、深度尺寸与归一化范围、指令和深度过期处理。

辅助接口没有接入官方 C++ 进程；这些测试不等同于真实 ZMQ / DDS / 传感器 / 电机联调。

## 测试划分和指标

基础与扰动组共 230 个 episode：

- 11 类平地指令 × 5 个初态 × 2 种动作模式 = 110。
- 7 组箱体/楼梯规格 × 5 个初态 × 2 种模式 = 70。
- 15 cm 楼梯上 10 种感知/动力学条件 × 5 个初态 = 50。

扩展组使用已有 procedural_v1 的 validation 清单：15 类地形 × 3 个难度 × 3 个布局，固定每个布局的 T0 初态，共 135 个 episode。参数未根据本轮结果调整。它不是对预训练分布严格未知的官方测试集；平地不同难度标签的几何相同，不能当成独立难度证据。

转向诊断额外比较仅平滑、仅髋关节缩放：2 个旋转方向 × 5 个相同初态 × 2 种处理，共 20 个 episode。该诊断在主测试发现差异后追加，属于探索性分析。

- 平地“完成”只表示达到 10 秒终点且未跌倒/触发停止，不代表速度准确；准确性单独报告平面速度向量与 yaw 角速度 RMSE。
- RMSE 从 0.5 秒后累计，包含启动/停止过渡；不是纯稳态误差。表格给出每个 episode RMSE 的算术平均。
- 地形通过：到达指定终点、横向偏差 <1.2 m、机体高度高于终点地面 0.17 m、保持直立，连续维持 0.5 秒。箱体主测试只要求登箱，不要求从另一侧下箱。
- 跌倒：直立程度过低或机体高度过低持续 0.2 秒；另记录越界、超时、安全阈值停止。
- 启停组在 6 秒切换为零速度。停止位移为发出零指令后的起终点水平位移，不是刹车路径总长；最终速度为末 0.5 秒平均。
- 记录 PD 力矩代理、实际执行器力矩、机体接触、绝对机械功和推理耗时。绝对机械功不等于电池耗电量。
- 每组 5 次或 3 次只能筛查现象。5/5 的 Wilson 95% 区间约为 [56.6%,100%]；不能宣称可靠性达到 100%。

扰动定义：随机固定 40% 缺失像素、5 cm 距离噪声、深度延迟 100/300 ms、1 秒深度全缺失、单扫描累积、60 N 侧推持续 0.2 秒、所有接触滑动摩擦系数设为 0.15、全身质量和惯量统一增加 20%。最后一项不是实际背包负载。延迟组继续执行策略，用于测模型容错，不启用辅助接口的 250 ms 新鲜度停止；不得理解成建议真机容忍同等延迟。

## 上机前仍需完成

1. 上游速度接收逻辑无新包时保留上次命令；深度循环也未见持续新鲜度停止。必须在实际执行进程中实现并联调 watchdog，不能仅依靠发送端 helper。
2. 实测相机/LiDAR 外参与时间戳、机体坐标、IMU 四元数、SDK 关节映射和电机方向。
3. 验证遥控接管、失联、传感器冻结、姿态异常、机械急停及阻尼回退。当前安全阈值触发后终止仿真，没有验证真实阻尼回退动作。
4. 在目标机载硬件上测端到端频率与最坏延迟。服务器 CPU 的推理时间不能代替 Jetson 测量。
5. 由操作者在保护条件下逐步验证平地、低速、低台阶。不能直接根据仿真通过率开展高箱、楼梯边缘或跨沟实验。

## 重跑入口

在服务器工作目录中，使用 `mujoco_env/bin/python deployment_suite.py --trials 5 --out runs/新的输出目录` 重跑基础组；程序拒绝覆盖既有目录。

扩展、诊断及视频入口分别为 `deployment_extended.py`、`deployment_ablation.py`、`deployment_videos.py`；各自输出目录也拒绝覆盖。重跑这些入口前，应明确指定新的输出路径，保留原始记录。完整代码快照、清单、逐次结果和轨迹见归档包。
