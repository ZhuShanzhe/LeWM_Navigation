# 后续阶段更新规范

本项目固定仓库：`ZhuShanzhe/LeWM_Navigation`。用户要求后续相关阶段性工作都更新到此仓库。

1. **开始阶段**：写清问题、假设、基线、训练/验证/最终划分、资源预算、成功/停止条件。采用新的日期/阶段目录，不把旧最终集反复当未触碰测试。
2. **实施**：保留准确代码版本、参数、种子、数据来源和额外监督。新增目录同步提供README。大资源只记录定位信息、版本、大小和SHA256，不记录凭据。
3. **验证**：先核验接口/数据和逐例结果，再写结论；记录失败、无改善和未测项。维护可复算的指标表，新增阶段时扩展测试但不删除旧科学断言来掩盖回归。
4. **整理**：更新根README的阶段导航、对应目录README、CHANGELOG、结果索引和provenance。冻结历史文件尽量不修改；必须修订时保留原文件并解释差异。
5. **提交推送**：检查差异与敏感内容，运行仓库验证和数值复算，确认目标remote；使用描述性commit，正常推送，不force push。已有他人更新时先读取并保留，不覆盖。
6. **交付**：提供GitHub提交链接、主要报告链接、验证结果和限制；只有远端确认后才能说上传完成。若权限或连接受阻，说明本地/服务器提交与远端不同步。

该约定适用于用户后续已授权的项目工作，不自动启动新的科研任务、收费资源或定时任务。当前实验已结束，历史自动回查已暂停。公开仓库状态不应被擅自改变。
